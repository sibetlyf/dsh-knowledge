# 使用与配置


[![GitHub release](https://img.shields.io/github/v/release/sibetlyf/dsh-knowledge)](https://github.com/sibetlyf/dsh-knowledge/releases/latest)
[![awesome · DSH plugin](https://awesome-dsh-plugin.com/badge.svg)](https://awesome-dsh-plugin.com)

`dsh-knowledge` 是面向 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的知识库插件。它不修改 DSH Agent Loop，同一个插件既能使用本地 SQLite，也能连接远程中央知识库。

## 回写与当前能力

### 分享导入的网络策略

从其他实例导入分享时，清单、文件内容及每次重定向都使用经过地址校验的直连请求，不继承 `HTTP_PROXY`、`HTTPS_PROXY` 或 `NODE_USE_ENV_PROXY` 的环境代理。这样实际连接的 IP 才与本次安全检查一致；只作用于笔记分享导入，不修改模型、联网搜索或其他插件的代理设置。

内网分享仍需确认本次访问或配置精确可信 Origin，确认不会扩展到其他分享；敏感地址拦截、逐跳校验和 HTTPS 证书验证保持启用。DSH 服务所在设备必须能直接访问目标分享；只有通过代理才能访问的公网分享不在当前直连策略支持范围内。不要通过关闭证书校验解决网络问题。

### 回写任务管理

知识工作区的“回写任务”，以及回答下方的“管理回写”，可查看本机持久化队列。按创建先后倒序显示，最新任务在前，每页最多 50 条，可按会话筛选，查看创建日期时间、尝试次数、下次重试时间、阻塞任务、失败原因及完成后的目标文档。旧记录未保存创建时间时明确标注，不用迁移时间冒充。即使连接中央知识库，这里管理的也是当前 DSH 客户端的队列。

- 网络等暂时错误最多自动尝试 5 次，之后保留为失败项，支持手动重试。重试复用原快照和已保存的计划，不使用后续对话重新生成旧任务。
- 服务正常关闭后恢复排队；进程意外退出时，在旧工作租约到期后恢复（租约为 60 秒）。失败项仍需处理，不会在每次启动时无限重试。
- 同会话正常按顺序回写；执行失败后间隔 5、15、60、180 秒自动重试（共最多 5 次尝试），不依赖错误文案。耗尽后保留失败记录、原始快照和写入计划，自动放行后续轮次；历史失败项也不再阻塞队列，可在回写任务中手动重试或取消。重试沿用幂等与版本冲突检查。服务停止、连接切换和远端执行租约等待不计入失败次数；其他会话可继续处理。
- 排队和失败项可立即取消。执行中的任务先记录取消请求，待当前执行退出后完成取消，期间不提前放行后续任务。取消请求在重启后仍有效；已写入内容不撤销，也不支持恢复已取消的任务。
- 页面通过共享长轮询接收状态变更通知，收到变化后立即查询最新状态，同时保留每 5 秒刷新队列的兜底。隐藏后暂停连接，重新显示或网络恢复后重新同步；原回答下也使用共享通知通道。确认记录不存在时清除旧等待状态，查询网络失败则提示重连，不误报任务不存在。历史版本未保存快照的任务不能安全重试。

当前版本提供可部署的多知识库、按需检索工具、本地与远程中央服务、文档型 Web 管理台，以及全局回写策略与安全直写协调：

- 回答完成后保存本轮快照，后台使用对应模型判断是否产生知识，并在原回答下方显示逐库回写结果。
- 知识标题、正文、自然语言标签和提取理由默认跟随本轮用户语言；代码、命令和技术标识保持原样。
- 回写结果只作为 UI 状态展示，在下一次模型请求前会被移除，不占用会话上下文。
- 全局“严谨 / 主动”回写策略保存在权威知识库服务中；远程客户端自动跟随中央设置。严谨模式不限制候选数量，而是以长期价值和较高置信度为门槛，接受用户明确陈述以及带具体来源的可靠调研结论。
- 可创建多个知识库，分别设定说明、默认标签和提取要求。
- 每个知识库可选择专用回写模型；未设定时跟随当前会话模型。
- 项目和会话挂载；会话默认继承项目，也可独立覆盖或关闭。
- 每个挂载支持仅召回、审核写入、直接写入，以及包含/排除标签和额外提取要求。
- `create / update / conflict / skip` 文档变更决策；更新会明确区分“补充新内容”和“修订过时原文”，不再用追加文本冒充原文修改。
- 原文修订使用唯一旧文本锚点和目标版本，由服务端在完整文档上原子执行。无关并发补充可安全重放；同一区域已变化时才转为真实冲突并进入人工解决。
- 未挂载知识库时，不召回、不提取、不回写。
- 全局与项目范围，以及偏好、事实、决策、流程、经验五类知识。
- SQLite WAL、FTS5 全文搜索、原子事务、完整版本历史和幂等提取任务。
- 回答前通过 DSH 官方提示组装接口提供有界的挂载库地图，并自动召回最多 3 条达到相关性门槛的摘要；不自动注入完整文档。模型可继续按“`knowledge_base_search` 找库 → `knowledge_search` 搜索指定库 → `knowledge_read` 读取文档”的顺序核对完整内容。
- 普通知识沉淀独立于主 Agent：主模型不暴露通用 `knowledge_write`，在回答结束后由独立提取调用处理，真实回写状态显示在回答下方。
- 用户明确确认“问题已解决”或“收集完成／结束”时，Agent 可通过 `knowledge_document_status` 更新对应知识状态，也支持回答后的自动提取。工具先搜索并读取目标文档，提交当前版本、用户确认原话和结论；仅解决其中一个问题时只修订对应段落，整篇保持开放。整篇结束保留正文和结论、生成历史版本并停止后续回写，可在界面重新打开。
- 状态更新遵循挂载权限：仅召回不能写，审核模式产生待审核候选，直接模式在版本核验通过后生效；敏感内容转人工审核。Agent 只能按实际工具结果说明“已标记”或“待审核”。不能用模型自述、疑问或普通“好了”封存文档，过期版本也不能确认结束。远程使用同一候选协议，服务端需同步升级到支持文档状态候选的版本，不会在远端失败后回退写本地。
- 用户明确要求时，模型可调用 `knowledge_base_create` 和 `knowledge_base_update` 创建或修改知识库，包括描述、标签、回写策略与专用回写模型；工具内部跟随当前 Provider 自动写入本地 SQLite 或远程中央服务，模型不传也不猜存储位置。
- `knowledge_base_create` 默认不保存专用 provider/model，回写沿用本机覆盖设置，否则跟随每次会话；即使连接远程知识库，也不复制远端模型配置。只有明确指定 `useCurrentSessionModel: false` 时，才要求并校验成对的专用模型参数。默认模式下旧调用夹带的模型字段会被忽略，并在结果中说明。
- 创建或修改工具不会自动挂载知识库，也不会回退、双写或同步到另一端；结果会明确返回实际写入的 `local` 或 `remote`。
- 搜索和读取由服务端按当前会话挂载、项目范围及包含/排除标签强制限权，读取句柄带签名且仅限当前会话。
- 本地与远程 Provider 使用同一接口；远程模式不做隐式双向同步。
- DSH“设置 → 插件”提供“知识库连接”卡片，可选择本地来源或填写中央服务地址和只写客户端令牌，保存后实时验证并切换 Provider。
- Bearer Token 仅保存 SHA-256 摘要，支持 `read / propose / write / admin` 权限及吊销。
- 认证 HTTP API，可作为其他 DSH 客户端和未来桌面端的中央知识库。
- 笔记软件式双栏文档界面：左侧以“知识库 → 文档”树形目录浏览和新建，右侧支持 Markdown 编辑与安全预览；目录按知识库懒加载并分页，只有打开文档时才读取正文。已有文档默认预览，新建文档默认编辑。
- 每个生效主题对应一篇真实 Markdown 文档；相似知识作为章节或增量内容写入同一文档。创建、改名、保存、归档和删除会同步 SQLite、全文索引、版本历史与物理文件。
- 独立的笔记工作区：在知识工作区上方提供可无限嵌套的目录树，支持 Markdown 与常见文本文件直接编辑，图片和 PDF 就地浏览，以及任意文件的拖拽移动、复制、重命名、下载和只读分享。主侧栏中的独立“已分享”页面集中管理本机链接，也能读取其他 DSH 的分享清单并将文档或完整目录复制到指定笔记目录。Markdown 编辑器提供标题大纲定位、文内查找与替换、选择结束后出现的浮动格式菜单和 `Ctrl/Cmd + F` 快捷键；每次保存会形成按需读取的页面历史，可预览、比较并恢复为新版本。笔记默认不参与知识检索、自动召回或 AI 回写。
- 分享导入保留 SSRF 防护；域名解析到内网或使用内网 IP 时，导入弹窗提示目标 Origin，管理员点击「允许本次内网分享并读取」后即可继续，无需预先配置白名单。确认仅绑定当前分享链接，修改链接或关闭弹窗即清除，不持久化；不允许借此访问回环、链路本地/云元数据地址或其他分享和接口，重定向仍逐跳校验。原有 `trustedShareOrigins` 和远程访问插件的可信 Origin 配置继续兼容。
- 知识文档自动生成双向链接：文档底部显示「关联文档」与「反向链接」，按共同标签、同一分组和标题主题计算同知识库内的关联；只读/定稿文档的预览中，正文里的 `[[文档标题]]` 会渲染为可点击链接，并在目标文档中显示反向链接；点击任意链接即可在文档间跳转。链接由读取时实时计算，不写入正文，不产生额外版本。
- 知识文档使用独立的“关联笔记”列表引用笔记文档或文件，正文不再插入引用语法。关系绑定稳定编号，笔记移动或改名不会失效；旧 `note://` 引用会在升级时安全回填为结构化关系。
- AI 可使用 `knowledge_note_list / search / read` 浏览和读取笔记，无需额外的语义授权；创建、更新、改名和移动先生成提案，展示变更后等待用户在下一轮对话确认。所有目标都使用当前会话签名句柄，远程操作继续服从令牌权限，删除仍有独立的明确授权边界，被知识文档引用的笔记不能直接删除。
- `knowledge_note_references` 单独负责查看、添加或移除知识文档与笔记的结构化关联，并在执行时重新检查知识挂载范围、写入模式和文档封存状态。
- 文档可标记为“已解决”或“已收集完成”。结束后的文档仍参与搜索和召回，但被服务端强制封存为只读；AI 回写、候选审核和人工编辑都必须先重新打开文档。
- 知识库管理拆分为“知识库”和“项目与会话挂载”两个工作区；支持按名称、描述、标签和模型即时搜索，避免知识库较多时逐张翻找。
- 随插件安装的响应式 Web 管理台，覆盖概览、文档树与编辑器、AI 候选审核和客户端令牌管理。
- DSH 浏览器端插件：在左侧工作区下方显示“知识库”，并在当前页面内打开管理面板。
- 明暗主题、键盘操作、窄屏布局以及不依赖颜色的状态标签。
- 制品自动归档：每轮对话结束自动归档**任务中涉及的所有文件**，包括 `present` 交付物、工具读写的文件、shell/workspace 变更、用户上传与 `@` 引用；归档副本内容寻址保存，并在自动创建/挂载的“制品归档”知识库中按文件类别生成可检索、可版本回溯、可双向链接的知识文档，无需上传、确认或审批。
- 可写知识库自动补齐：项目没有任何可写挂载时，自动把「默认知识库」以可写模式挂载到项目，避免“未挂载可写知识库”而无法写入。
- 自动分类与免审核：AI 提取优先复用已有知识库和文档分组，必要时自动新建知识栏目并直接写入；后台自动批准非冲突的待审核候选，笔记整理草案直接落盘。
- 制品文件浏览：管理台新增「制品文件」页面，支持按格式预览、下载任意文件，并打开对应知识文档进行编辑、调整分组或移动。

## 制品自动归档

`artifactArchiveEnabled` 默认开启。插件在 `agent/turn-stopping` 读取本轮会话事件，收集任务涉及的所有文件：成功 `present` 声明的文件（含 shell 生成后声明的文件）、所有工具参数中出现的文件（`read` / `read_image` / `str_replace_editor view` 读取，`write` / `edit` 写入，以及其他工具的输入输出）、shell 命令中的路径与 workspace-changes 记录的本轮变更、用户 `@` 引用的文件，以及用户上传的附件（通过 Host `attachments` 服务读取）。每个候选都会校验存在性、常规文件、大小与排除规则；归档与知识写入在后台串行执行，不阻塞对话，也不进入模型上下文。

- 归档副本位于知识库数据库相邻的 `artifacts/`（可用 `artifactArchivePath` 修改），按 SHA-256 内容寻址；相同内容只保存一份，每次内容变化都保留旧版本字节。**具体文件保存在归档文件夹**，数据库中的知识文档只保存文件路径、归档副本链接、元数据、关键词与读取提示，默认不复制正文（`artifactArchiveStoreContent: false`；设为 `true` 才把抽取正文写入数据库）。
- 每个制品对应一篇知识文档（标题形如 `制品 · reports/q4.md`，上传附件为 `制品 · 用户上传/<文件名>`，类型 `fact`），按文件类别归入 `制品 · 文档 / 表格 / 演示 / 图片 / 压缩包 / 音视频 / 代码 / 其他` 栏目；内容变化时原地更新并形成新版本，删除源文件后归档副本仍可读。
- **PDF 论文**：自动识别后提取标题、摘要、关键词、年份、arXiv/DOI 与类别，标题为 `论文 · <标题>`，归入 `论文 · <类别>` 分组；首次出现论文时只创建一个「论文库」，摘要与关键词写入数据库并立即进入全文索引。非论文 PDF 不触发论文库。可用 `artifactArchivePaperEnabled: false` 关闭。
- 默认归档所有格式（`artifactArchiveExtensions: ['*']`）；可改成扩展名列表收窄文件工具写入的范围，读取/引用/变更/交付/上传仍按“任务涉及即归档”处理。所有来源都受单文件大小上限与排除模式约束。
- 源码文件会归档并参与双向链接，但不写入工作日报素材，避免日报被代码文件淹没。
- 每篇知识文档包含文件路径、关键词与读取提示；PDF、Office/ODF、文本会抽取文字用于生成关键词（默认不写入正文），图片、压缩包、音视频和其他二进制保留元数据并以归档副本为准。
- 管理台「制品文件」页面可预览图片、PDF、纯文本、音视频并下载任意格式，或一键打开对应知识文档进行编辑、调整分组与跨库移动；归档副本保持不可变。
- 首次归档时自动创建 `artifactArchiveBaseName`（默认 `制品归档`）知识库，并以“仅召回、不参与对话回写”（`writeMode: none`）的方式挂载到当前项目，后续搜索与自动召回直接命中制品内容。已有挂载设置不会被覆盖；知识库被人工归档后停止自动归档。
- 每轮第一个模型步骤检查项目挂载：没有任何可写挂载时，自动把「默认知识库」以 `autoWritableMountWriteMode`（默认 `direct`）挂载到项目；已有可写挂载、被显式关闭或设为仅召回的默认挂载都保持原样。可用 `autoWritableMountEnabled: false` 关闭该行为。
- 对话知识提取优先复用已有文档分组；现有知识栏目都不适合时，`autoCreateKnowledgeBases` 允许模型自动新建一个知识栏目（知识库）并直接挂载写入；每日自动新建知识库数量由 `autoCreateKnowledgeBasesMaxPerDay`（默认 3，0 表示只复用）限制，同名栏目复用。
- `autoApprovePendingEnabled` 开启时，后台自动批准非冲突的待审核候选（默认 2 分钟一次，且每轮结束触发），提取完成时也会立即补跑一次；`noteOrganizeAutoApprove` 让笔记整理草案直接落盘；真实冲突与凭据类内容仍保留人工确认。
- 自动整理触发方式：`autoOrganizeTrigger: turn` 每轮对话后整理；`interval` 按 `autoOrganizeIntervalMinutes`（默认 30 分钟）批量整理，归档仍按轮执行，只有知识提取会合并到间隔窗口。
- 自动工作纪要触发方式：`worklogAutoUpdateTrigger: turn` 每轮/每次知识更新后刷新；`interval` 按 `worklogAutoUpdateIntervalMinutes`（默认 30 分钟）批量刷新。日报的每日定时生成仍由工作日报自身的 `scheduleEnabled` / `scheduleTime` 控制。
- `tokenSavingEnabled` 默认开启：提取输入上限 12000 字符、输出 3072 tokens，自动召回最多 2 条、上下文字符上限 3000；关闭后使用配置中的原始值，适合需要更高精度的场景。
- 管理台「自动化」页可以图形化设置上述自动审核、两种触发模式、间隔和 token 节省；保存后立即更新运行参数。
- 自动整理只读取既有文档的标题、标签、分组和约 600 字摘要；自动双向链接由本地元数据/关键词推导，不调用模型；需要完整正文时再通过 `knowledge_read` 读取，避免把整库文档塞进上下文。
- 知识文档工具栏的「优化格式」和工作日报的「优化排版」调用编辑模型只改格式/表达，要求保留事实、数字、路径、链接与依据编号，并去掉重复和 AI 腔；优化结果作为新版本保存。
- 默认排除 `node_modules`、`.git`、`.dsh`、`.env`、证书私钥、SQLite 数据库等路径；单文件超过 `artifactArchiveMaxFileBytes` 或正文超过 `artifactArchiveMaxChars` 时跳过或截断。
- 只读接口 `GET /knowledge-control/v1/artifacts`（最近 500 条记录）和 `GET /knowledge-control/v1/artifacts/<id>`（下载副本），与其他管理接口一样要求同源管理台请求头。
- **选择文件夹导入**：在「制品文件」点击「导入文件夹」，可逐级浏览本机目录或直接输入路径；确认后递归扫描（默认最多 800 个文件），跳过依赖/版本库/构建目录与符号链接，进入后台归档队列，继续自动分类、论文识别、双向链接与索引。接口为 `GET /knowledge-control/v1/folders` 与 `POST /knowledge-control/v1/artifacts/import`。
- **插件联动**：宿主提供 `dshKnowledge` 服务，其他插件可调用 `ingestRecord` / `ingestFiles` / `search` / `listBases` / `introduceBase`，或订阅 `knowledge/write` 事件；未安装知识库插件时应降级。

完整配置、解析规则与限制见 [制品自动归档](artifacts.md)。

## 对话中引入知识库

在对话输入框键入 `@`，候选菜单会多出「引入知识库」分组，列出当前连接下所有生效知识库；可继续输入名称/说明过滤，已挂载的库会标注“已挂载”。

同一个 `@` 菜单还提供「导入文件夹…」：选择后直接打开知识库的文件夹浏览器，确认当前目录即可递归导入；输入框工具行的文件夹按钮也执行同一操作。文件继续走归档、分类、论文识别、双向链接与索引流程，完成后右下角弹出气泡显示新增/更新/跳过等汇总，点「查看明细」可逐项查看文件、类别、目标知识库、分组和论文分类。

- 选中后会插入一个「知识库 · <名称>」引用块，可在发送前删除或继续输入问题；
- 发送时插件把该知识库以**仅召回（`writeMode: none`）的会话挂载**加入当前会话，因此本轮及后续自动召回、`knowledge_search`、`knowledge_read` 都能使用它；
- 不会把本轮对话或提取的知识写回被引入的知识库；
- 远程只读令牌没有挂载写权限时，发送会被阻止并提示错误，不会静默降级；
- 可在管理台「知识库与挂载」中查看或关闭该会话挂载。

## 后台状态与思维链接图

界面采用阅读优先布局：正文、导航、知识目录与工具栏字号整体放大；知识目录是可滑出的抽屉（顶部目录按钮或空状态里的「浏览知识目录」打开），默认不占用第三列，文档区域占满宽度；主导航已去掉冗余序号。

减少重复操作：再次进入「知识文档」会自动恢复上次打开的文档；没有历史时自动打开当前知识库中最近更新的一篇文档；编辑既有文档后停止输入约 1.4 秒会自动保存（状态栏显示“自动保存中…/已自动保存”），不再必须点击保存；保存按钮仍保留作为手动兜底。

- **后台状态卡**：管理台顶栏右侧常驻一张后台状态卡（窄屏自动隐藏），每 3 秒读取 `GET /knowledge-control/v1/background-status`。自动归档时显示 `自动归档 2/5 · 文件名` 和进度条；知识回写排队/处理或工作日报整理时显示对应任务；完成 12 秒内提示 `已归档 N 个文件`；空闲时显示“后台自动整理”，点击可跳到「制品文件」「回写任务」或「工作日报」。
- **思维链接图**：左侧「思维链接」页把整库文档画成动态力导向图。节点颜色按文档分组，大小按链接数，边区分正文引用/共同标签/同一分组/主题相关；支持拖动节点、滚轮缩放、悬停高亮邻居、点击节点打开文档，顶部可切换知识库并重新计算，底部提供可键盘操作的节点清单，右上角可把当前关系图导出为 PNG 图片。
- **从文档进入**：每篇文档底部「双向链接」面板右上角提供「关系图」，直接打开该知识库的整图。

## 本地模式

默认数据目录不再固定写入 C 盘用户目录：Windows 上优先使用插件所在非系统盘（例如插件在 `G:` 时使用 `G:\dsh-knowledge`），也可以用环境变量 `DSH_KNOWLEDGE_HOME` 指定目录。首次启动若发现旧目录 `C:\Users\<用户>\.dsh\knowledge`，会复制到新目录（旧目录保留为备份）。通常无需显式配置路径：

```yaml
- id: knowledge
  name: 'dsh-knowledge'
  config:
    backend: local
    extractionEnabled: true
    defaultScope: project
    autoRecallLimit: 3
    autoRecallMinScore: 0.2
    recallMaxChars: 5000
    exposeApi: false
    exposeWeb: true
```

本地管理台默认开启。它使用独立的同源管理接口，不要求开放远程 API，也不要求输入访问令牌；侧栏“知识库”安装后即可使用。任何能访问 DSH Web 的用户都具有本地管理权限，因此把 DSH 暴露到公网时，应继续使用反向代理登录保护整个 DSH 站点。

提取模型默认沿用刚完成回答的 provider/model。可在单个知识库中设置专用回写模型；“本机回写模型”是当前客户端的最高优先级覆盖，适合中央知识库在不同客户端使用不同模型。实际优先级为：本机覆盖 → 知识库专用模型 → 当前会话模型 → 以下兼容性后备配置：

```yaml
    extractionProvider: deepseek-official
    extractionModel: deepseek-chat
```

独立模型必须先在 DSH 的模型设置中注册。不论使用 Kimi 还是其他会话模型，首次超限后都会保持原 provider/model，用精简提示和低推理重试，不会暗中换模型。

提取输出达到模型上限时会自动用双倍预算重试一次（最高 8192 tokens）。其他提取失败会将幂等任务标为 `failed`，失败任务最多可重新领取两次，并在回答下方记录回写通知，不会阻断下一轮。

## 中央服务端

需要作为中央知识库时，进入“知识库 → 访问管理”，点击“开启远程 API”。开关会持久化，页面会显示其他客户端应填写的完整 API 地址；然后为每台客户端创建独立令牌。已撤销令牌可以永久删除。

部署自动化仍可通过配置直接启用认证 API：

```yaml
    backend: local
    exposeApi: true
    apiToken: !!js process.env.DSH_KNOWLEDGE_API_TOKEN
    apiPrefix: /knowledge-api/v1
    exposeWeb: true
    webPath: /knowledge
```

`DSH_KNOWLEDGE_API_TOKEN` 至少 24 个字符。该值只用于创建或恢复 bootstrap admin 身份；数据库只保存摘要。服务端没有 TLS，非回环部署必须放在 HTTPS 反向代理之后。

启用后访问 `http://<DSH 地址>:<端口>/knowledge`。本地管理台使用同源管理权限；开放给其他客户端的 `apiPrefix` 仍强制要求 Bearer Token。管理台和 API 均由 DSH 自身 WebServer 提供，不需要额外容器。

管理台功能：

- 查看准确的知识、候选和提取任务统计。
- 创建和编辑多个知识库，管理默认标签与提取要求。
- 在知识库页切换全局“严谨 / 主动”回写策略。
- 管理当前项目挂载和会话覆盖，设定召回、写入模式与标签范围。
- 在左侧知识目录中搜索、新建和切换文档，在右侧进行 Markdown 编辑与安全预览；文档区域随窗口自适应，窄屏时知识目录切换为抽屉。
- 在“笔记工作区”中建立多级目录，直接编辑 Markdown、文本、JSON、YAML、代码和配置文件；Markdown 笔记支持标题大纲定位、文内查找/替换，以及选中文字后的段落、标题、列表、引用、代码、链接等快捷格式菜单。页面历史按需加载单个版本，可查看逐行差异并将任意旧版恢复为新的保存记录。工作区同时支持上传、拖放、复制、移动、搜索、下载和就地浏览图片与 PDF；知识文档底部的“关联笔记”栏用于查看、打开、添加和移除资料关系。
- 查看 AI 提取依据和真实增删差异，直接通过、编辑最终文档后通过或拒绝候选。
- 创建、查看和撤销客户端令牌；新令牌原文只显示一次。

输入框的 `@` 菜单支持独立的「笔记文档」分组：跨目录按标题搜索，选中后引用准确的文档 ID，发送时生成当前会话可用的读取句柄。不会混入普通知识条目、目录或附件，也不会授予修改权限；沿用原菜单的方向键、Enter、Tab 与 Escape。详见 [笔记文档引用](../docs/note-mentions.md)。

知识库的 `description` 同时用于读取和回写路由：它以轻量目录形式告诉模型每个挂载库覆盖什么主题，`knowledge_base_search` 也用它匹配当前信息需求；文档正文不会随目录注入。主模型不执行内容回写，所有回答都在完整结束后进行一次独立的严格提取，同时判断长期价值、目标知识库、重复、更新与冲突；用户明确要求保存时也走同一条回答后链路。挂载只表示“可选”，不代表每次回答都要写入。`extractionInstructions` 用于匹配后继续限定具体收录规则。

笔记工具与知识回写相互独立。列举、搜索和读取不要求用户先发送授权句式，也不要求知识库挂载；仍需有效的当前会话句柄和远端服务访问权限。创建、更新、改名和移动支持自然表达需求，但首次工具调用只生成待确认提案，不写入；AI 需展示具体变更，长预览通过 `knowledge_note_preview` 完整读取后，等待用户下一轮对话确认，再用 `knowledge_note_confirm` 执行原提案。不使用弹窗，也不要求复制固定授权段落；提案有效期为 15 分钟，重启、过期、改需求或版本冲突时需重新提案。永久删除仍必须在当前消息中明确提出，不能沿用历史授权。

工具先用 `knowledge_note_list` 浏览目录或按名称搜索，也可用 `knowledge_note_search` 查找非目录节点；随后使用返回的精确句柄。局部修改使用 `replace_range`，多处修改使用同一原文快照的 `batch_edit`，保留未修改正文；仅真正新增内容才使用追加，整篇替换需明确说明影响范围。`knowledge_note_create` 未指定父目录时写入笔记根目录，指定目录时必须使用列表返回的文件夹句柄。本地和远程模式由当前 Provider 决定，工具不猜测存储位置。管理台中的笔记文档和普通文件可从目录列表或工具栏下载。

创建示例：

```json
{
  "draft": {
    "name": "DSH 项目规范",
    "description": "只匹配 DSH 插件开发、架构决策和部署规范相关对话",
    "defaultTags": ["dsh", "project-rule"],
    "extractionInstructions": "只收录已确认且可跨会话复用的结论"
  }
}
```

局部修改标签或描述时使用 `PATCH /knowledge-bases/:id`，请求体为 `{"patch":{"description":"...","defaultTags":["..."]}}`。

## 远程客户端

先在中央实例的“知识库 → 客户端令牌”中为每台客户端分别创建令牌。普通 DSH 客户端建议选择 `read + propose`。`write` 是当前中央服务的全局写权限，同时允许直接写入知识、管理知识库、挂载和笔记；只在客户端确实需要这些能力时授予。令牌原文只显示一次。

其他 DSH 客户端安装本插件后，打开“设置 → 插件 → 知识库连接”，选择“远程”，填写中央实例的知识库 API 地址和客户端令牌，再点“验证并连接”。插件会先验证地址和令牌，成功后立即热切换，并把连接持久化到 DSH 数据目录；令牌不会在页面或控制接口中回显，只能覆盖。

侧栏“知识库”入口会先通过控制接口确认当前实例是否启用了管理台，确认后才加载管理页面。管理台默认随本地模式启用；只有 profile 显式设置 `exposeWeb: false` 时才关闭。入口不会把未注册的 `/knowledge` 误交给 DSH Web 主页面，因此不会触发 `dsh-plugin-desktop` 参数错误。

如需用配置文件或环境变量部署，也可以直接设置 Provider：

```yaml
- id: knowledge
  name: 'dsh-knowledge'
  config:
    backend: remote
    remoteUrl: 'https://knowledge.example.com/knowledge-api/v1'
    remoteToken: !!js process.env.DSH_KNOWLEDGE_REMOTE_TOKEN
    extractionEnabled: true
```

远程地址必须是 HTTPS；只有 `localhost` 和回环 IP 的测试地址允许 HTTP。普通客户端建议只分配 `read + propose` 权限。
远程客户端连接的是中央库，不会复制或同步一份本地数据库；断网时无法召回或回写。侧栏管理台仍在当前 DSH 内打开，插件通过同源代理携带已保存的远程令牌访问中央 API，不使用跨域 iframe，也不会把令牌交给浏览器。远程模式隐藏“访问管理”，API 开关和客户端令牌仍由中央 DSH 管理。每台客户端仍需用自己的项目/会话标识挂载所需知识库。

# 挂载知识的引用笔记

已挂载、可召回的知识文档引用了笔记后，AI 可以通过 `knowledge_note_references list` 取得笔记句柄。读取笔记本身无需额外语义授权；更新时若传入 `knowledgeHandle`，会检查当前挂载和实际引用关系。引用关系不代替修改确认：普通会话的正文更新仍需先展示提案，再由用户下一轮确认，并核验目标版本；不会因为知识库可召回就自动获得直接写入或删除笔记的权限。远端服务原有访问权限继续生效。
伙伴轻量关注只使用手动指定的记录位置，不处理依据中的笔记引用。宿主通过 `dshKnowledgeNoteRecording` 读取、校验并更新指定笔记。

## 文档自动同步与保存保护

- 当前打开的知识文档、可编辑笔记约每 5 秒检查一次版本，有变化才读取正文。不扫描整个文档库；后台标签暂停请求，网络失败自动退避重试。
- 未编辑时自动更新并保留滚动位置；有未保存修改或正在输入时保留编辑器，提示“文档有新版本”。差异窗口可对照最新内容手动整理，应用为草稿后再保存；放弃草稿需要确认。
- 页面保存携带读取时的版本；保存过程中继续输入的内容仍标记为未保存。服务端拒绝过期版本，不自动覆盖，也不自动创建被删除的文档。
- `knowledge_note_read` 返回 `note.version`。`knowledge_note_update` 的正文追加、替换必须携带 `expectedVersion`；版本过期需重新读取和合并，重命名不需要正文版本。
- 指定关注记录的内容哈希检查保留，实际写入进一步在笔记写入队列内校验版本。知识文档的版本校验与写入位于同一数据库事务。
- 这是自动同步与冲突保护，不是多人逐字协同。远端知识服务也需要更新到支持版本校验的版本。
# 内置工作日报

在「知识库 → 工作记录 → 工作日报」使用，无需独立日报插件。适配 DSH 0.1.7-rc.2。
采集默认关闭；但知识库发生自动写入（对话回写、制品归档）后，插件会为该写入所在项目自动开启采集、加入项目范围并启用每日生成，无需手动配置；也可随时在采集设置中调整或关闭。

「采集设置 → 选择目录」提供可展开的工作目录树。目录树仅根据当前 DSH 实例的默认工作目录、观察到的会话工作目录、当前会话和手动添加的路径构建，不读取磁盘目录，也不把中央接收的其他机器路径或手工补记当成本机项目；自动补出父级节点，父目录没有会话也能勾选。这里的“本机”是运行 DSH 的实例，并非浏览器所在电脑。展开与勾选相互独立；方向键浏览/展开，空格勾选。旧版混合目录表会按来源修复，本地与远端同时出现的路径需有本机会话依据才能恢复；历史配置不删除、不重写，缺少本机依据的已选路径单独收在“其他已保存目录”中。

采集设置只在“本机采集”和“中央整理”两个分区保留小型「？」提示，支持悬浮、键盘聚焦及点按，Esc 先关闭提示；权限、离线和错误消息仍直接显示。目录树首次显示只展开本机默认工作目录的祖先，使默认目录可见，其子目录及其他分支仍收起；当前 DSH 使用服务启动工作目录作为未指定工作区或 cwd 时的默认值，不取当前会话或远端中央目录。默认值不可用时全部收起，不因已有勾选自动展开；主动添加目录时仍展开定位。手动收起后，轮询刷新不重新展开。采用紧凑单行布局，展开高度受限，支持一键收起且不改变勾选；树下不再重复展示当前目录路径。模型刷新按钮与选择框同排，刷新失败保留原选择并显示错误。

树外的「包含所选目录的子目录」默认关闭，保持原来的路径精确匹配。开启后，例如选择 `/work`，会包含 `/work` 本身及 `/work/project-a` 等任意层级子目录，但不包含 `/workshop`。树中下级标注「上级已包含」，不会逐个写入选择列表；取消父级后，原本单独勾选的子目录仍保留。若只需要部分下级，应取消父级后分别勾选。依据是会话工作目录（`header.cwd`），不是会话分组或终端里的 `cd`；保存后仅影响后续采集，不扫描历史。排除会话仍然优先。

子目录匹配按路径层级处理末尾分隔符及 `.` / `..`；支持 POSIX 绝对路径（区分大小写）、Windows 盘符和 UNC 共享路径（不区分大小写、兼容正反斜杠）。相对路径只精确匹配，不按服务进程目录推算，也不解析符号链接。该开关只保存在当前 DSH 实例，远程模式和中央离线时也可通过「仅保存本机采集」修改，不改变其他实例的范围。

支持日期、补记、来源核对、编辑、导出、历史版本和持久化重试；日报数据独立存储，不混入知识文档。
试用版升级会复用原 worklog/worklog.sqlite；部署时应先移除旧 dsh-worklog bundle 注册，保留数据库，防止双重执行。

### 知识库更新触发自动日报

知识库每次自动写入都会同步成为当天日报的素材，并在后台实时刷新日报：

- 触发来源包括对话知识回写（新建或更新知识文档）、制品自动归档（新增或更新制品文档），以及管理台手工编辑等任何内容变化；手工变更由后台巡检（约 1 分钟）发现并纳入。
- 每次写入记录一条 `知识库更新：<文档标题>` 来源，包含知识库、文档、动作、项目、会话与轮次，可在日报「来源」中核对或排除。
- 连续多次写入按 8 秒防抖合并为一次后台整理，由原有整理队列调用模型生成/更新当天日报；页面可查看进度，失败沿用既有重试策略。
- 手工编辑过的日报不会被自动覆盖，自动整理检测到手工正文后跳过本次刷新；可在日报中手动重新整理。
- 首次触发时会为该写入所在项目开启采集并加入项目范围：原有选择范围保持不变，仅追加该项目；若日报采集原本关闭，则同时启用每日生成（默认 23:00，沿用日报设置中的时区与模型）。
- 远程中央模式下，知识库更新作为来源进入上传队列，由中央按自己的整理配置生成；本机不运行生成队列。
- 可用插件配置 `worklogAutoUpdateEnabled: false` 关闭「知识库更新 → 日报」联动；关闭后日报仍可按原有手动/定时方式使用。

### 中央统一日报

日报跟随知识库连接：本地模式的 DSH 是日报存储/整理节点；远程模式仅采集和补传，浏览、编辑、模型列表和定时配置均来自已连接的中央知识库。**中央与采集端都需要升级到支持统一日报的版本**，中央需开启知识库远程 API。旧中央不支持时显示升级提示，不悄悄切回本地日报。

- **本机采集**：启用开关、项目范围、本地工作目录、排除会话由每个 DSH 实例独立保存。断网时也可单独关闭采集；已授权进入上传队列的素材仍会补传。
- **中央整理**：时区、模型、每日整理时间和开关统一管理。上传素材按中央时区归日；客户端模型 ID 不直接用于中央生成。请在中央模型列表选择可用模型，避免中央没有对应本机模型。远端模式不会运行原本地整理队列。
- **断网补传**：来源先写入本地 SQLite 上传队列，指数退避重试（最长间隔 5 分钟），可手动重试。来源使用持久实例 ID + 原记录 ID 去重；成功回执后清掉队列中的正文，只保留去重凭证。中央记录被排除后，重复上传不会重新纳入。
- **目标隔离**：队列绑定采集时的中央地址，切换连接不把旧来源发到新中央；回到原地址后继续。同一地址的中央实例 ID 改变时暂停上传并提示，不自动将旧数据交给替代实例。
- **历史迁移**：点击「迁移本地历史」并确认后，来源进入上传队列，已有日报/历史版本作为中央历史归档，不覆盖中央正文。本地数据仍保留；不迁移原本地模型/定时配置或未完成的生成任务。重复迁移可去重。
- **认证和权限**：中央使用现有 Knowledge Bearer Token：读取需要 `read`，来源上传/补记/整理需要 `write`，中央设置和历史日报迁移需要 `admin`。本机网页入口仍需 Host 登录认证。这里是同一中央的共享工作记录，不是按令牌隔离的私人日记，勿给不可信人员中央读取权限。

来源跨实例汇总，但不会尝试在本机打开其他实例的会话。补传状态在页面显示；中央离线时明确报错，本机采集设置仍可修改。

### 每日定时整理

在「采集设置 → 中央整理 → 定时整理」开启，选择每日时间（默认建议 23:00），按中央设置中的 IANA 时区运行。默认关闭；保存后从下一个设定时间开始，浏览器无需保持打开，但中央 DSH 服务必须运行。

每次整理目标为该日期截至执行时的已采集/补记素材，使用同一模型设置及持久任务队列。采集开关与整理开关独立：关闭采集后，仍可定时整理手工补记。不覆盖人工编辑的正文；无新素材不调用模型；到点后新增的素材可手动更新日报。既有任务运行时等待其结束再判断是否需要整理。

每日触发标记与任务入队在同一事务中持久化；服务重启只补最近一次错过的日期，不批量回填历史。网络失败沿用最多三次自动尝试，失败后在对应日期手动重试。设置中显示最近一次定时检查结果。修改执行时间或时区从新设置的下一次时间生效；关闭定时不取消已入队任务，可在日报页面单独取消。
